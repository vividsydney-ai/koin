# Addendum — KO-ABUSE-001: RPC abuse hardening (via /loop)

## Scope
Harden `complete_lesson`, `award_koin_points`, `check_in_streak`, and `add_friend_by_qr` against replay/mint abuse (single migration per loop rules).

## Audit findings (worse than assumed)
- Live `complete_lesson` (migration 011 version) awarded lesson XP, quiz bonus, KP, and streak-milestone XP/KP on **every** attempt — replay = infinite farm.
- `award_koin_points` granted to `authenticated, anon` with **no auth guard** — any user could mint Koin Points directly.
- `check_in_streak` had no GRANT statement (PUBLIC by default), no auth guard.
- `complete_lesson` granted to `anon` unnecessarily.

## Shipped
- `supabase/migrations/20260718000048_abuse_hardening.sql`
  - Idempotent XP/KP via `xp_events` ledger EXISTS checks.
  - Quiz bonus on first correct attempt only.
  - KP on first completion only; streak milestone ≤ once/day.
  - 30s minimum completion time.
  - `award_koin_points` + `check_in_streak` internal-only (REVOKE from authenticated/anon/PUBLIC).
  - `complete_lesson` anon grant revoked.
  - `add_friend_by_qr` 20/day cap.
- `tests/migrations/048_abuse_hardening.test.ts` (11 assertions)
- `scripts/smoke/abuse-hardening.mjs` (production replay/mint/speedrun smoke test)

## Verification
- Gates: tsc ✅, lint ✅ 0 errors, vitest ✅ 325 passed / 5 skipped
- Migration applied to production Supabase ✅
- Production smoke: **12/12 PASS** (replay → 0 XP, xp_events unchanged 2→2, KP unchanged 10→10, direct mint denied, direct check_in_streak denied, 5s completion rejected)
